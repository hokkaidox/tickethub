# ERD Catalog

Таблицы Catalog: площадки, схемы залов, места, мероприятия и цены. Кто чем владеет между сервисами — в [architecture.md](../architecture.md), раздел «Места: кто чем владеет».

```mermaid
erDiagram
    venue ||--o{ layout : "схемы залов"
    layout ||--o{ segment : ""
    layout ||--|{ seat : ""
    segment ||--|{ seat : ""
    layout ||--o{ event : ""
    event ||--|{ event_price : ""
    segment ||--o{ event_price : ""

    venue {
        UUID id PK
        String name
        String address
        String time_zone "IANA, Asia/Almaty"
        String currency "ISO 4217, валюта новых мероприятий"
    }
    layout {
        UUID id PK
        UUID venue_id FK
        String name "«Большой зал», «Большой зал, сцена выдвинута»"
        Integer seat_count "N, считается при создании"
    }
    segment {
        UUID id PK
        UUID layout_id FK
        String name "Партер, Балкон, VIP"
    }
    seat {
        UUID layout_id PK, FK
        Integer seat_no PK "0..N-1, сквозной технический номер"
        UUID segment_id FK "not null"
        String section "nullable, подпись на билете"
        String row "nullable"
        String number "номер на билете"
    }
    event {
        UUID id PK
        UUID layout_id FK
        String title "печатается на билете"
        String description "nullable"
        String status "DRAFT, PUBLISHED, CANCELLED"
        timestamptz starts_at
        timestamptz ends_at "nullable"
        String currency "ISO 4217, копия venue.currency при создании"
    }
    event_price {
        UUID event_id PK, FK
        UUID segment_id PK, FK
        Decimal price "numeric(12,2), в валюте мероприятия"
    }
    outbox {
        UUID id PK "UUIDv7, задаёт порядок публикации"
        UUID aggregate_id "id мероприятия, ключ партиции Kafka"
        String event_type "EventPublished, EventCancelled"
        jsonb payload
        timestamptz created_at
    }
    idempotency_key {
        String caller PK "sub из JWT; до этапа 3 пустая строка"
        String key PK "заголовок Idempotency-Key"
        String request_hash "хэш тела запроса"
        Integer response_status "null, пока запрос выполняется"
        jsonb response_body
        timestamptz created_at "хранится 24 часа"
    }
```

## Сущности

| Таблица | Что хранит |
| --- | --- |
| `venue` | Площадка: название, адрес, часовой пояс и валюта |
| `layout` | Схема зала площадки. Одна площадка может иметь несколько схем: разные залы или один зал в разных конфигурациях |
| `segment` | Ценовая зона схемы: «Партер», «Балкон», «VIP». Сегмент принадлежит схеме, цены у него нет. В зале без зон один сегмент на все места |
| `seat` | Место схемы. `seat_no` — технический номер от 0 до N−1, его видят Reservation и Order. `section`, `row`, `number` — то, что напечатано на билете |
| `event` | Мероприятие на конкретной схеме |
| `event_price` | Цена сегмента на конкретном мероприятии. Один зал на разных мероприятиях продаётся по разным ценам. Валюты у цены нет: она одна на мероприятие, в `event.currency` |
| `outbox` | События для Kafka, записываются в одной транзакции с изменением мероприятия. Polling publisher удаляет строку после отправки |
| `idempotency_key` | Ответы на админские `POST` создания, отправленные с `Idempotency-Key`. Не связана с остальными таблицами; устройство — в [API Catalog](api.md), раздел «Ключ идемпотентности» |

Сектор и сегмент — разные понятия. Сектор — подпись на билете, сегмент — ценовая зона. Часто они совпадают, но первые ряды сектора могут стоить дороже остальных.

## Правила, которые проверяет код

- Схема зала неизменна целиком: места, сегменты и привязка мест к сегментам. Изменённый зал — новая схема. Только поэтому `seat_no` можно передавать в другие сервисы: номера никогда не сдвигаются. Сегменты тоже не меняются: перенос места в другой сегмент молча поменял бы его цену у уже опубликованных мероприятий, а удаление сегмента оставило бы его цены и места без пары.
- Схему можно удалить, только пока на неё не ссылается ни одно мероприятие.
- Пустые `section` или `row` значат, что в зале нет такого уровня нумерации (кинозал без секций, амфитеатр без рядов), а не секцию по умолчанию. Место однозначно задаёт тройка `(section, row, number)` внутри схемы: `UNIQUE NULLS NOT DISTINCT (layout_id, section, row, number)`. Обычный `UNIQUE` считает NULL разными значениями и пропустил бы два «места 37» без ряда. Индекс — последняя защита, дубликаты отсекает валидация запроса.
- У каждого места ровно один сегмент, места без сегмента нет. Цена есть только у сегмента, поэтому место без сегмента осталось бы без цены. У каждого сегмента хотя бы одно место: пустой сегмент только требовал бы цену при публикации.
- Закрыть часть мест на мероприятие нельзя: для этого создаётся отдельная схема без этих мест.
- Мероприятие публикуется (`DRAFT → PUBLISHED`), только если у каждого сегмента его схемы есть цена в `event_price`.
- `segment_id` в `event_price` принадлежит той же схеме, что и мероприятие.
- Цену получает Order по паре `(event_id, seat_no)`: место → сегмент → цена мероприятия. Цены после публикации менять можно, в заказе фиксируется цена на момент его создания.
- `EventPublished` несёт `eventId` и `seatCount` = `layout.seat_count`.
- После публикации у мероприятия не меняются `title`, `starts_at`, `ends_at`, `layout_id`: они попадают на проданные билеты (или, как схема, в места Reservation). Меняется только `description`. Отменённое мероприятие не меняется вовсе. Перенос даты с уведомлением покупателей не моделируется.
- Пока мероприятие в `DRAFT`, смена `layout_id` удаляет его цены: они принадлежат сегментам старой схемы.
- Валюту задаёт площадка. Мероприятие копирует `venue.currency` при создании и больше её не меняет: если площадка сменит валюту, цены уже созданных мероприятий не поменяют смысл. Все цены мероприятия в его валюте, поэтому смешать валюты в одном зале нельзя по устройству таблиц, а не проверкой.
- `starts_at` хранит момент времени. Показывается он в часовом поясе площадки `venue.time_zone`, а не клиента.

## Что намеренно не моделируется

Цены по расписанию (ранние продажи по датам), скидки и промокоды, закрытие мест на одно мероприятие, организаторы и права на редактирование, пересчёт валют и показ цен в другой валюте, перенос даты мероприятия, зоны без рассадки.
